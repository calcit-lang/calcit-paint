# Resource root for relative paths / 相对资源的 resource root

## English

- Add `calcit-paint.core/set-resource-root!` (C-safe buffer v1 export `set_resource_root_calcit_ffi_v1`) so applications can resolve relative `:image :file-path` values against a project directory instead of the process working directory.
- Relative paths join the configured root; absolute paths stay unchanged; an empty string restores the default working-directory behavior. The renderer still skips missing files but now reports the resolved path on stderr.
- Cache identity uses the resolved path, so the same logical path does not collide across roots.
- Exercise the new path in `scripts/check-cookbook.sh` by setting the root and rendering the image asset, and cover the resolution logic with a Rust unit test.
- Register the new export in the Actions symbol audit and the `check-examples` step.

Validation:

- `calcit ./calcit.cirru edit format` zero diff; `--check-only` passes; quality baseline unchanged at 11 schema-dynamic positions; zero dynamic-method findings.
- README `format-md`/`check-md`; all nine `check-examples` targets, including `set-resource-root!`.
- `calcit test --require-match` (16 passed); `./scripts/check-cookbook.sh` renders the asset through the configured root; `./scripts/check-creative-art.sh` hash unchanged.
- `cargo fmt --check`, 103 Rust tests, strict Clippy, release build, and the Actions provenance/export audits.

## 中文

- 新增 `calcit-paint.core/set-resource-root!`（C-safe buffer v1 导出 `set_resource_root_calcit_ffi_v1`），让应用把相对 `:image :file-path` 解析到项目目录，而不是进程工作目录。
- 相对路径会拼接到配置的 root；绝对路径保持原样；空字符串恢复默认工作目录行为。渲染器仍会跳过缺失文件，但 stderr 会报告解析后的完整路径。
- 缓存 key 使用解析后的路径，避免同一逻辑路径在不同 root 下冲突。
- 在 `scripts/check-cookbook.sh` 中设置 root 并渲染图片资源以覆盖新路径，并用 Rust 单元测试覆盖解析逻辑。
- 在 Actions 导出符号审计与 `check-examples` step 中登记新导出。

验证：

- `calcit test --require-match`（16 passed）；`./scripts/check-cookbook.sh` 通过配置的 root 渲染图片资源；`./scripts/check-creative-art.sh` hash 不变。
- `cargo fmt --check`、103 个 Rust 测试、strict Clippy、release build 与 Actions 来源/导出审计。
